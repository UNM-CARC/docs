Network Connections

  • Dialup connections are available upon request. You must be an authorized AHPCC or Alliance user in order to be granted access. Please use the help page to request the dialup numbers.
  • Telnet is available, but not recommended due to poor security.
  • SSH1, SSH2, and OPENSSH are available.

Email
The AHPCC supports PINE and Netscape email systems. PINE is a text-only email system. Netscape may be either text-only or HTML.

PPP

  • The instructions below are specific to AHPCC. The linux PPP README file contains the general instructions.
  • Edit /etc/hosts to add any machines you commonly use. The file /etc/resolv.conf should list the domain, search and nameservers.
  • Two programs are required to start PPP: pppd and chat. You will need to be superuser for most of the configuration. First edit /etc/syslog.conf and add the two lines local2.* [TABs] /var/log/ppp-log local2.* [TABs] /dev/console
  • Then refresh the syslog daemon, syslogd, using kill-HUP pid (use ps to get the pid). The second line is useful for debugging and can be deleted later if desired.
  • Make the directory /etc/ppp. You will need to create two files. The first consists of options for pppd and is called options. It should contain
    connect "/usr/sbin/chat -v -f /etc/ppp/dialppp" crtscts modem defaultroute :198.59.173.3 mru 552 mtu 552 noipdefault ipcp-accept-remote
  • The -v turns on verbose mode during login and can be removed once your setup is completed. The second file is for chat and is called dialppp (or another name if the options file is changed). This file should be owned by root and only readable and writeable by root. The file should be something like
    ABORT BUSY ABORT 'NO CARRIER' '' ATZ OK AT&F0&C1&D2&K3&Q5 OK ATDT2778393 CONNECT '\r' name:--name: username word: password\q slip: ppp
  • where username and password are replaced with the appropriate parameters. More information can be obtained from the man pages for pppd and chat
  • To activate PPP, type (as root) /usr/sbin/pppd /dev/cua3 115200
  • where /dev/cua3 should be the appropriate serial port (COM4 in this case). To exit PPP, as root execute ps to get the process id, then kill -9 pid
