5.1 Purpose of Queuing System

More efficient use of the computing resources can be made through the use of a queuing system. All jobs with expected run times greater than eight hours should be submitted through the batch queuing system. Some tolerance for long running jobs running interactively will be given for testing or unusual situations. The effect of too many of these jobs can slow down the performance of the entire AHPCC computing systems. Therefore, we reserve the right to limit the use of the interactive running of long running jobs.

5.3 Batch Queuing System -- LoadLeveler

The current implementation of the queuing policies for the SP1 is done using IBM's LoadLeveler. LoadLeveler is a complex system with many potential pitfalls. Therefore, it is highly recommended to start with an existing example LoadLeveler script and a standard environment setup. The following are the basic LoadLeveler commands.

llsubmit: submits a LoadLeveler command file. The syntax is llsubmit [filename] where filename is a file containing a set of LoadLeveler commands.

llq: checks queue status. llq -u [userid] lists userid jobs only. llq -l [job_id] gives a long listing for the specified job. llq -s [job_id] gives node allocation details which can be helpful in tracking down problems with jobs not starting.

llcancel: llcancel [job_id] cancels a previously submitted job.

llhold: llhold [job_id] places a job on hold. llhold -r [job_id] will release the job.

5.4 Linux Batch Queuing System -- Job Queuing System (JQS)

******** Under Development ***********

The Job Queuing System (JQS) is being written to provide a queuing system for the Linux cluster. It is planned to be a simple system with a deterministic scheduling algorithm that guarantees that a job will run no later than a time determined at submission.
