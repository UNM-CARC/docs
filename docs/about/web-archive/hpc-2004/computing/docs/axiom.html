Description

AXIOM is a computer algebra system (a.k.a. symbolic manipulator) which evolved out of IBM's SCRATCHPAD II and is currently owned by NAG (Numerical Algorithm Group). AXIOM is the only general purpose computer algebra system which is truly object oriented and in which object types are well defined and integrated; this allows for reusable code and relatively bug free development but sometimes trips novice users. AXIOM's ability to run in compiled mode also makes it particularly suitable for large problems.

Documentation

AXIOM has excellent on-line hypertex documentation which contains most of what is found in the main reference book and more, and through which the source code can be accessed. The main reference book is
Jenks, R. D., Sutor, R. S. (1992); AXIOM: the Scientific Computation System; New York, NY, USA: Springer-Verlag.
which is available in bookstores or by phoning 1-800-springe with your credit card in hand.

Also check out AXIOM's home page.

AXIOM at the High Performance Computing, Education and Resehpcerch Center

The following documentation is somewhat outdated. For example, you may see references to the no longer available machine zia.hpcerc.unm.edu.

Besides the ASCII version of the following file, the directory /usr/local/axiom_hpcerc contains a lot of goodies, including a script xon_hpcerc which allows running remotely utilities (related or not to AXIOM) very conveniently.

Axiom at the HPCERC:
You essentially have 3 options:

  • OPTION 1 (less convenient, less pretty, more robust):
    • xhost + on your local console/terminal
    • rlogin onto acoma, taos or zia and in some window there:
      make sure that you have the substance of /usr/local/axiom_hpcerc/cshrc_for_axiom in your HPCERC .cshrc file (otherwise source it).
    • setenv DISPLAY "your local console DISPLAY location" (if you do not know what it is, echo $DISPLAY on your local console; you should get something like cutemachinename.unm.edu:0.0 or about 10 numbers with periods sprinkled around).
    • axiom
  • OPTION 2 (more convenient, more pretty, less robust):
    • xhost + on your local console/terminal
    • rlogin onto ANY machine at the HPCERC make sure that you have the substance of /usr/local/axiom_hpcerc/cshrc_for_axiom in your HPCERC .cshrc file (otherwise source it).
    • setenv DISPLAY "your local console DISPLAY location" (if you do not know what it is, echo $DISPLAY on your local console)
      If you are at the HPCERC and use a .rhosts file, all the previous steps are superfluous (except the .cshrc one, of course, which is a one time deal).
    • doaxiom (prettier) or doaxiom x (more robust) or any other variations (see /usr/local/axiom_hpcerc/bin/doaxiom_hpcerc for details)
  • OPTION 3 (more convenient still)
    • Install /usr/local/axiom_hpcerc/bin/xon_hpcerc in your REMOTE bin directory. Make sure that it has execute permission (ls -l ~/bin); if not cd ~/bin; chmod u+x xon_hpcerc).
    • At the HPCERC, make sure that the machine names and your user name as it is at the remote location are in the file .rhosts, and that it has universal read permission (chmod a+r ~/.rhosts) xon_hpcerc anyMachineAtThehpcerc.hpcerc.unm.edu
      with, maybe, additional options toggled (see /use/local/axiom_hpcerc/bin/xon_hpcerc)
      This is very convenient (especially if aliased) to run ANYTHING at the HPCERC (or anywhere except on your local system).
    • An xterm window with all environment variables set properly will appear (see CAVEAT in xon_hpcerc's source code).

In that window: make sure that you have the substance of /usr/local/axiom_hpcerc/cshrc_for_axiom in your hpcerc .cshrc file (otherwise source it).
doaxiom (or its variations; see above).
